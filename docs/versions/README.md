# 開発計画と実施記録

このdirectoryは、今後の調査・要件・Step計画・確認結果を残す場所です。[ROADMAP](../../ROADMAP.md)は将来目標、[CHANGELOG](../../CHANGELOG.md)は変更要約、公開候補の詳細は[Release notes](../releases/v1.0.0.md)が役割を持ちます。仕様の全文を作業記録へ重複掲載しません。

## 新しい記録を始める

[TEMPLATE](TEMPLATE.md)をもとに、対象版なら`vX.Y.Z.md`のような名前で作成します。将来版/個別作業の名称は対象と役割が分かるようにし、作成日・対象commit・開始状態を記載します。作業前の記載、計画、実施結果を混ぜず、古いStatusだけで現在の完了を判断しません。

1. 依頼の目的・範囲・対象外を確認し、現行実装と関連する仕様を調べる。
2. 調査結果と未決事項、保持する契約・制約をもとにStepと合格条件を具体化する。
3. 依頼されたStep/範囲を実施し、各Stepの変更・確認・失敗・残件を記録する。範囲外を自動で完了扱いにしない。
4. 必要なtest/lint/build・文書検査、運用者の手動反映/Browser/実機確認をそれぞれ記録する。
5. 合格条件と実績を照合し、未検証・未実施と次の担当工程を残して総括する。

全仕様を毎回読む固定リストは置きません。[AGENTSの参照案内](../../AGENTS.md#変更範囲に応じた参照)から、変更範囲の正本と実装・関連testを選びます。コマンドは[DEVELOPMENT](../DEVELOPMENT.md)、運用は[OPERATIONS](../OPERATIONS.md)、配布は[RELEASING](../RELEASING.md)を参照し、実行区分を維持します。

## 記録の粒度

| 項目 | 記録する内容 |
|---|---|
| 根拠 | 対象commit/候補、調査file、関連する正本と制約、未決事項 |
| 変更 | 何を・なぜ変えたか、対象file、互換性と対象外 |
| 確認 | 開始directory、実行command・環境・exit code・結果。未実行は理由と担当 |
| 手動結果 | 運用者の報告と直接照合を区別。Browser/実機、build/実行、サービス/OS再起動を分ける |
| 失敗・残件 | error/原因/対処・再確認、未検証範囲、停止条件、次Step |

記録やreportの存在だけで成功と判断しません。保存report/hashを別候補の結果へ書き換えず、新しい実施は別の記録を残します。個人のhome/drive/LAN IP/USB個体値や実dataを公開用記録へ混ぜず、必要な内部証拠は公開外で保管し、公開文書の理解に必須としません。

## 実行境界と文書更新

AIのread-only調査/build/test/文書生成と、OS反映・Pico書込み・実data/IR等のManual onlyを区別します。詳細は[AGENTS](../../AGENTS.md#実行境界)に従い、文書のcommand例を実行承認にしません。

結果が現在の仕様を変える場合は、対応する正本を更新して作業記録から相対リンクします。CHANGELOGは変更の要約、Release notesは候補の機能・asset・環境別確認・既知制約に限定します。版番号・lock・配布物は文書作成だけで自動更新しません。
