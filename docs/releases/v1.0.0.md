## 主な機能

- FrontendからRoom/Device/IR Adapter、CommandとStateful Schema/Stateを設定し、信号を登録・学習・明示送信できる。
- 条件別の必須/任意/適用外、候補・数値範囲/刻み、表示情報を設定し、省略/0/false/空文字を区別する。既存Stateと衝突するSchema更新や、登録済み信号の意味を崩す編集を拒否する。
- raw_samples/raw/code/preset_commandの4形式。codeは明示したbackend_rawまたはcapability確認済みnative_codeを使い、deliveryとrepeat進捗を表示する。自動再送・自動fallbackは行わない。
- Data Health、保存planと確認に基づくMaintenance、Backup隔離復元演習、Trash/復元、operation履歴を提供する。
- 共通configと先頭--configでloopback待受、data/保守root、daemon socket、Pico serialを指定する。専用service userとsystemd/Nginxの標準配置を使う。

仕様の正本は[API](../API.md)、[DATA_SCHEMA](../DATA_SCHEMA.md)、[STATEFUL_SCHEMA](../STATEFUL_SCHEMA.md)。操作は[IR_GUIDE](../IR_GUIDE.md)と[OPERATIONS](../OPERATIONS.md)を参照してください。

## 既知制約と公開前の残件

- 認証なしの単一ローカル運用者向けAPIです。インターネットへ直接公開しないでください。ECHONET Lite/Matter、高度な自動化、スケジュール実行、複数Pico完全管理は未対応です。
- RAW実行は38kHz、codeはPANASONIC_40。captureはraw_samples専用です。sentは送信処理の結果で、家電の実状態や設定到達を保証しません。
- 短いcapture/早期422と無入力timeoutの事例があります。入力変化の原因や遅延信号の確実な受信は未確定です。詳細は[TROUBLESHOOTING](../TROUBLESHOOTING.md)を参照してください。
- v0.11.0は過去snapshotの限定的な互換性記録で、条件付きSchemaを含む現dataの一般的復旧先にしません。復旧時は新版側を先に保全して差分を確認し、旧側へ自動mergeしません。
- 旧dataはruntimeからTrashへ退避した履歴があり、物理最終削除は未実施の別運用判断です。期限到来だけで削除しません。
- 旧候補の2026-11-02監査にあったmoderate12件は、開発依存の更新後、e7318deの2026-11-04監査で検出0件となりました。これは同候補のnpm依存に対する当日の結果であり、将来やアプリ全体の無脆弱性を保証しません。
